資料格式｜哪些是網站常用的資料格式？附加好用的 JSON 視覺化工具

資料格式 JSON XML YAML Markdown

在現代網站與前端開發中，資料格式的選擇主要圍繞著 「網頁結構傳遞」 以及 「資料交換（API）」 兩大需求。

1. 網頁本身的「結構」與「樣式」格式（靜態與互動基礎）

這些是組成一個網頁最核心、瀏覽器原生看得懂的語言：

HTML (HyperText Markup Language)

  • 用途：網頁的骨架。定義文字、圖片、區塊等網頁結構。

  • 特點：由標籤（Tags）組成（如 <div>, <p>等）。

CSS (Cascading Style Sheets)

  • 用途：網頁的外觀與排版。負責顏色、字型、響應式 RWD 佈局等。

  • 特點：讓網頁從單調的黑白文字變成精美介面的關鍵。

JS (JavaScript)

  • 用途：網頁的靈魂與互動邏輯。

  • 特點：前端程式語言，控制動態互動、API 資料請求。

2. 「資料交換與 API 傳輸」格式（前後端溝通）

當網頁需要跟伺服器要資料（例如：抓取天氣、取得使用者清單、讀取資料庫）時，最常使用的序列化格式。

JSON (JavaScript Object Notation) —— 主流

  • 用途：前後端資料交換、設定檔（Configuration）、資料儲存。

  • 為什麼受歡迎：

  1. 它本質上就是 JavaScript 物件的寫法，前端處理起來極為直覺。
  2. 結構輕量、人類看得懂、電腦解析速度也快。

XML (Extensible Markup Language)

  • 用途：早期網頁資料交換、RSS 訂閱源、大型企業系統整合、Sitemap 網站地圖。

  • 特點：長得像 HTML，使用嚴格的標籤包覆（<tag>...</tag>）。雖然結構嚴謹，但因為語法太冗長、檔案較大，現在在一般前端 API 開發中已經大多被 JSON 取代了。

YAML / YML

  • 用途：專案設定檔、靜態網站生成器、CI/CD 部署流程。

  • 特點：縮排非常乾淨、人類閱讀性極高，不用寫一堆括號或引號。

3. 其他網頁常見的資料與傳輸格式

Markdown (.md)

  • 用途：文章寫作、部落格內容、專案說明文件（README）。

  • 特點：純文字格式，但透過簡單的符號（如 #, *）就能標示標題和粗體，常見於筆記與技術部落格。

CSV / JSON 匯出檔

用途：表格資料備份、數據匯出。

開發實用小工具：JSON 檢視與視覺化神器

雖然 JSON 很實用，但有時候拿到一大包 JSON 原始檔案時，資料是密密麻麻的排在一起，肉眼看實在是很不方便，因此可以使用一些方便好用的工具，提升資料的易讀性。

1. 使用 Chrome 套件直接美化 JSON

如果是用瀏覽器直接開啟 JSON 檔案或 API 網址，可以安裝這款 JSONView Chrome 套件。安裝後，瀏覽器就會自動把亂成一團的 JSON 排版成有縮排、有色彩的高亮格式，閱讀起來直覺很多。

2. JSON Crack：把複雜結構畫成心智圖

遇到結構超深、資料很龐大的 JSON 時，可以使用 JSON Crack。只要把 JSON 程式碼貼進去，它就會自動把階層資料轉化成清晰的視覺化節點圖（Node Graph），整個架構瞬間一目了然。

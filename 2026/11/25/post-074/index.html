JS語法筆記 | 打開抽屜串珠珠：for...in 迴圈與 join()

JavaScript JS語法筆記 join() for...in

在整理資料或處理網頁內容時，常常會遇到兩種很實際的需求：第一種是「手邊有一些零散的項目，想把它們串成一段完整的文字」；第二種是「手邊有一個物件，想把裡面的欄位或屬性逐一拿出來看」。

這時候就很適合使用 for...in迴圈 搭配 join()。

join()：把陣列元素串起來

join() 是 JavaScript 陣列的內建方法，用途是 把陣列中的所有元素串接起來，回傳成一個新的字串。

可以想像成，陣列裡的每個元素是一顆珠子，傳進 join() 括號裡的 「分隔符號」就是每個珠子中間的分隔裝飾。如果沒有指定分隔符號，預設會用逗號 , 串接。

基本語法

實際運用：組裝麵包屑、標籤列或網址路徑

需留意的地方

  • 不會修改原本的陣列：join() 會回傳一個全新的字串，原本的陣列內容依然維持不變。

  • 遇到 null 或 undefined 會變成空字串：如果陣列裡混有 null 或 undefined，join() 會把這兩個值當成 '' 處理，不會直接報錯。

for…in：逐一走訪物件的可列舉屬性

for...in 是一種迴圈語法，主要用來 走訪物件（Object）中可列舉的屬性名稱（Key）。

可以把它想像成拿著一份清單，逐一清點抽屜或櫃子上的每一個標籤名稱：每次迴圈，變數拿到的都是 「屬性名稱（Key）」，接著可以用 obj[key] 把對應的 值（Value） 取出來。

基本語法

實際運用：動態讀取設定檔或整理欄位資料

當拿到一個物件（例如表單欄位設定、字典對應表或 API 回傳的物件），想把所有欄位都跑過一遍做檢查或組裝時，for...in 就派上用場了。

當同時使用 join() 和 for…in 的常見錯誤

1. 拿 for…in 來走訪「陣列」

for...in 是設計來走訪 物件的屬性名稱（Key），不是拿來走訪陣列元素的。
如果對陣列使用 for...in，迴圈拿到的 key 會是字串形式的索引（'0'、'1'、'2'），要走訪陣列元素本身，優先用 for...of 或陣列的 .forEach()、.map()。for...in 留給 物件（Object） 使用最恰當。

2. 存取物件屬性時，誤用點記法 obj.key 而不是中括號 obj[key]

在 for...in 迴圈裡，key 是一個變數（裡面裝的是屬性名稱字串，例如 'name'）。如果寫成 userProfile.key，JavaScript 會去物件裡找一個字面名稱真的叫做 key 的屬性，結果往往是 undefined。

結語

join() 負責把分散的陣列元素俐落串成一段文字，for...in 則把物件裡的屬性名稱逐一攤開來檢視。可以簡單記住 「陣列串接看 join()、物件屬性巡檢看 for...in（並用 obj[key] 取值）」。

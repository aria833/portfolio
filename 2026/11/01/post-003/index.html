Bloom Memories 效能優化｜載入時間從 22s 縮短至 1.76s

效能優化 Bloom Memories 網站加速

將專案 Bloom Memories 發布之後，我發現初次進到網站的載入時間有點長。透過開發人員工具（DevTools）的 Network 檢查，發現 load 時間竟然高達 22 秒！

為了提供更好的使用者體驗，決定進行效能優化。

一、 問題定位：兇手是圖片

為了確認主要問題出在哪裡，使用瀏覽器開發人員工具進行了檢查：

  1. 按 F12 開啟開發人員工具。
  2. 切換到 Network 頁籤。
  3. 勾選 Disable cache（停用快取）。
  4. 將 Throttling 設定為 No throttling（無節流）。
  5. 重新整理網頁並等待載入完成。
  6. 查看 Network 的請求清單，尤其是 Size、Time 與總計資訊。

檢查後發現問題非常明確——圖片是主要因素。光是首頁的 5 張圖片就佔了 6.1 MB。

相較之下，其他資源顯得輕量許多：

  • JavaScript 主檔：74.9 KB
  • CSS：56.6 KB
  • 明信片資料：約 16 KB
  • 其他 JavaScript：大多只有幾 KB

因此，我決定先針對圖片進行優化，後續視情況再進行程式碼層面的調整。

二、 優化策略規劃

  • 第一階段：圖片格式與尺寸（本次實作）
    除了 Logo 使用 SVG 以外，其餘圖片主要為 PNG 與 JPEG。由於大部分不需要透明背景或特殊效果，決定全面轉為新一代的 WebP 格式。
    💡 注意事項：轉檔後務必確認圖片品質，尤其是文字、細節和透明背景是否有失真。

  • 第二階段：延遲載入圖片（Lazy Loading）
    將使用者一開始不需要看到的圖片延後載入時間。

  • 第三階段：範例明信片冊按需載入
    原本初始化時會載入三本範例明信片，可改為：

    1. 首頁僅載入相冊封面。
    2. 使用者點擊特定相冊時，才動態載入該本明信片的內容。
    3. 使用者翻頁時再逐步載入後續圖片。

（本次因階段一成效顯著，階段二、三暫緩）

三、 實作：使用 Mac 終端機批次轉換 WebP

為了有效率地處理大量圖片，使用 Mac 終端機透過 Homebrew 安裝的 WebP 工具 進行批次轉換。

Step 1：安裝 WebP 工具

開啟終端機，輸入以下指令安裝：

brew install webp

Step 2：移動到目標資料夾

如果不知道完整的資料夾路徑，最快的方法是：

  1. 在 Finder 中找到圖片資料夾（例如 sample-yamagata）。
  2. 直接把資料夾拖曳到終端機視窗中，終端機就會自動帶入完整路徑。
  3. 在路徑前方加上 cd ，然後按下 Enter。

cd /你的專案路徑/images

Step 3：執行批次轉換腳本

使用以下 Shell Script 將資料夾內所有的 PNG、JPG、JPEG 轉為 WebP（設定品質為 80）：

指令功能解析：

  • find .：搜尋目前資料夾。
  • -type f：只處理檔案。
  • *.png / *.jpg / *.jpeg：指定要搜尋的圖片格式。
  • -q 80：設定 WebP 品質為 80（在畫質與檔案大小之間取得平衡）。
  • -print0：安全處理包含空格的檔名。
  • if [ ! -f "$output" ]：避免重複覆蓋已存在的 WebP 檔案。

Step 4：確認轉換前後的檔案大小

檢查整個圖片資料夾目前的總容量：

du -sh .

(原始圖片資料夾總容量約為 73MB)

計算轉換後的 WebP 總容量：

find . -type f -iname "*.webp" -exec du -ch {} + | tail -n 1

(轉換後的 WebP 總容量縮減至 5.8MB)

可以看到，改用 WebP 後，圖片資料夾大幅「輕量化」，壓縮率高達約 92.1%！

Step 5：確認 WebP 圖片正常顯示

開啟轉檔後的圖片，確認畫質無異常、文字清晰，且沒有產生多餘瑕疵。

Step 6：修改程式碼中的圖片副檔名

將專案程式碼中所有對應的圖片副檔名替換（例如：將 .png / .jpg 改為 .webp）。

Step 7：開啟本地端 Server 測試與清理原始檔

開啟 Local Server 驗證網頁運作正常、圖片皆能成功顯示後，使用終端機指令清理原本的 PNG/JPG 舊檔：

find . -type f \( -iname "*.png" -o -iname "*.jpg" -o -iname "*.jpeg" \) -delete

Step 8：重新部署專案

將優化後的圖片與程式碼推送到遠端伺服器進行部署。

Step 9：使用 Chrome Network 檢測最終成效

再次開啟 DevTools Network 頁籤，進行 Disable cache 狀態下的首頁載入測試。

四、 結語與成果

在完成 第一階段的圖片格式轉換 後，成效非常顯著：

  • 優化前： 首頁載入耗時 22 秒
  • 優化後： 首頁載入縮短至 1.76 秒
  • 容量壓縮比： 圖片總體積由 73MB 降至 5.8MB（壓縮率 92.1%）

因為僅執行第一階段的 WebP 轉換就已經達到了極為理想的效果，因此原本規劃的第二階段（圖片延遲載入）與第三階段（動態拆分相冊）就先暫緩執行。

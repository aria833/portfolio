認識 HTTP Method｜如何正確向伺服器發號施令？

HTTP Method CRUD 冪等性 (Idempotent)

在介紹 CRUD｜4個最基本的資料操作動作 時，有稍微提到 HTTP Method，這篇就要來主要介紹 HTTP Method。

什麼是 HTTP Method？

當我們在瀏覽器輸入網址、點擊按鈕或送出表單時，客戶端（Client，如瀏覽器或前端程式） 會向 伺服器（Server） 發送一個 HTTP 請求。請求中一定會包含一個 Method（方法），用來明確告知伺服器這次操作我們想要做什麼。

在實務開發中最常用、也最核心的方法有 5 個：

1. GET 取得資源（Read）

  • 用途：向伺服器請求獲取特定資源。

  • 特性：資料會附加在 URL 網址的 Query Parameters 後方
    例如：https://api.example.com/posts?id=1

    • 不會改變伺服器端的資料狀態。
    • 可以被瀏覽器快取（Cache）。

2. POST 新增資源（Create）

  • 用途：向伺服器提交新資料，通常會在伺服器端建立一筆全新的資源。

  • 特性：

    • 資料放在 Request Body（請求主體）中傳輸，不會暴露在網址上。
    • 會改變伺服器端的資料狀態。
    • 不是冪等的（Non-idempotent）：重複送出相同的 POST 請求，可能會在資料庫建立多筆相同的資料（例如重複送出表單導致建立兩筆訂單）。

  • 常見情境：註冊帳號、發布新貼文、送出購物車結帳。

3. PUT 完整替換資源（Update）

  • 用途：更新指定的資源。如果該資源不存在，有些 API 設計允許它直接建立（Upsert）。

  • 特性：

    • 必須傳入資源的 完整內容。如果漏掉某些欄位，伺服器可能會把那些沒傳的欄位清空或覆蓋為預設值。
    • 是冪等的（Idempotent）：不管呼叫一次還是十次，只要傳入相同的完整資料，最終伺服器的結果都一樣。

  • 常見情境：完整更新使用者個人檔案（把姓名、信箱、頭像全部重新覆蓋一次）。

4. PATCH 局部更新資源（Update）

  • 用途：對指定的資源進行部分修改。

  • 特性：

    • 只需傳遞想要修改的欄位即可，未傳遞的欄位保持原樣。
    • 視實作而定，有些 PATCH 具備冪等性，有些則否。

  • 常見情境：單純修改使用者的密碼、將文章狀態從「草稿」切換為「已發布」。

5. DELETE 刪除資源（Delete）

  • 用途：要求伺服器刪除指定的資源。

  • 特性

    • 是冪等的（Idempotent）：第一次刪除成功，第二次再刪除同一筆資源時，伺服器可能回傳「找不到該資源（404）」，但伺服器的整體狀態不會再改變。

  • 常見情境：刪除貼文、移除購物車內的特定商品、註銷帳號。

更了解 HTTP 的請求方法之後，在前端串接 API 時能更正確選擇對應的 Method。

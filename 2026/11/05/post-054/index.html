HTTP 狀態碼｜讀懂伺服器的三位數密碼

HTTP 狀態碼 HTTP Method

在網頁開發與前後端串接的過程中，當我們發出 請求(Request) 後，伺服器除了回傳我們想要的資料外，最重要、也最常拿來判斷狀況的就是 HTTP 狀態碼（HTTP Status Code）。

什麼是 HTTP 狀態碼（HTTP Status Code）？

HTTP 狀態碼是一個由 3 位數字 組成的代碼，被放在 HTTP 回應（Response） 的最前端。這串數字的 第一個數字 就可以看出狀態的大方向。

  • 1xx：伺服器正在處理（資訊回應(Informational)）

  • 2xx：請求成功（Success）

  • 3xx：需要重新導向（Redirection）

  • 4xx：客戶端錯誤（Client Error，通常是前端或使用者的問題）

  • 5xx：伺服器端錯誤（Server Error，通常是後端程式崩潰或主機出事）

區間範圍 類別名稱 涵義與常見情境
100 - 199 資訊回應(Informational) 伺服器已收到請求，正在繼續處理（前端開發中比較少直接接觸）
200 - 299 成功 (Successful) 請求被成功接收、理解並處理
300 - 399 重新導向 (Redirection) 需要後續操作才能完成請求，通常用於網址搬遷 或 登入跳轉
400 - 499 客戶端錯誤 (Client Error) 例如傳錯參數、找不到網頁、沒帶 Token
500 - 599 伺服器端錯誤 (Server Error) 雖然語法沒錯，但後端程式執行報錯或資料庫連線失敗

經典狀態碼

在日常寫程式或除錯時，不用記住全部代碼，只要掌握以下幾個常見的就足夠應付 90% 的情境：

成功系列 (2xx)

  • 200 OK：一切順利！最常見的成功回應，GET 或 PUT 請求成功後通常回傳這個。

  • 201 Created：已建立。當使用者用 POST 成功新增一筆資料（例如註冊成功、發表新文章）時最常使用。

  • 204 No Content：無內容。請求成功執行了（例如 DELETE 刪除成功），但伺服器不需要回傳任何資料給前端。

客戶端錯誤系列 (4xx)

  • 400 Bad Request：請求無效。通常是前端傳送的 JSON 格式錯誤、缺少必要欄位，或是參數型態不對，伺服器看不懂。

  • 401 Unauthorized：未授權。使用者 還沒登入 或憑證（Token）已過期，無法驗證身份。

  • 403 Forbidden：禁止存取。伺服器認得你是誰（有登入），但你 沒有權限 造訪這個資源（例如一般會員想去改管理員後台）。

  • 404 Not Found：找不到資源。你輸入的網址不存在、或者向 API 請求一個已經被刪除的特定 ID 資源。

伺服器端錯誤系列 (5xx)

  • 500 Internal Server Error：伺服器內部錯誤。後端程式碼寫錯，導致伺服器當場崩潰。

  • 502 Bad Gateway：閘道錯誤。通常發生在負載平衡器（Load Balancer）或反向代理伺服器（如 Nginx）後面找不到活著的應用程式伺服器。

  • 503 Service Unavailable：服務暫時無法使用。伺服器目前過載（流量太大）或正在進行維護停機。

如果在寫前端專案（例如用 JavaScript 串接 API）卻發現畫面沒有資料時，可以先

  1. 打開開發者工具 (F12) → Network (網路) 分頁：再次觸發你的 API 請求。

  2. 看 Status 欄位：

    • 如果看到 4xx：立刻檢查前端程式碼–是不是網址拼錯？參數有沒有漏掉？

    • 如果看到 5xx：通常不用改前端了，直接去找後端工程師或檢查伺服器 Log。

只要掌握了這些狀態碼的語意，在前後端串接時就能迅速定位問題根源，大幅縮短 Debug 的時間。

同步與非同步｜Overcook 拿高分的秘訣

同步（Synchronous） 非同步（Asynchronous） AJAX

在網頁開發與程式設計的世界裡，同步（Synchronous） 與 非同步（Asynchronous） 是決定程式執行效率、使用者體驗流暢度的核心觀念。

什麼是同步與非同步？

想像一下你在玩《Overcooked》：

1. 同步（Synchronous）：

  • 遊戲情境：
    你把米丟進鍋裡開始煮。因為是完全同步，你不能離開，必須站在瓦斯爐前面發呆、盯著進度條，直到米煮好為止。在這段時間之內：

    • 你不能切菜
    • 你不能洗盤子
    • 畫面上的所有其他事情全部停擺，因為你的角色被「阻塞（Blocking）」在瓦斯爐前了

  • 結果：只要煮個飯花 5 秒鐘，這 5 秒內廚房完全無法運作。如果客人點了三道菜，你一道一道這樣排隊依序做，分數絕對低到爆炸。

2. 非同步（Asynchronous）：

  • 遊戲情境：
    在同樣的遊戲情境下，如果是非同步，你會這樣做：

    • 發起任務：你把飯丟進鍋煮。這就像發送了一筆 AJAX 請求–飯開始在背景（Background）煮了。
    • 不阻塞、繼續做事：你不需要站在原地發呆，立刻轉身去洗盤子、切番茄、送餐。這時主線任務完全沒有被卡住，保持極高效率。
    • 回呼通知（Callback / Event）：當飯煮好的瞬間，畫面跳出提示（就像 Promise 成功回傳資料或 async/await 拿到結果）。你看到通知後，立刻轉身過去把飯端起來擺盤。

  • 結果：瓦斯爐在背景幫你煮飯，你同時處理好幾樣工作，整個廚房行雲流水、高分過關。

為什麼 JavaScript 需要非同步？

要理解為什麼前端開發這麼依賴非同步，必須先知道一個規則：JavaScript 是一門「單執行緒（Single-threaded）」的語言。

這代表 JavaScript 引擎在同一個時間點 只能做一件事。

試想一下，如果 JavaScript 採用的是 完全同步（Blocking） 的模式：

  1. 當在overcook遊戲裡，你來了大量的訂單。
  2. 因為是完全同步，你放進米的瞬間，你的角色當場被「定格（Freeze）」在烤爐前，動彈不得。
  3. 後面的客人等得不耐煩了，訂單就會一直被取消，你的廚房評價也一直往下掉。

因此，非同步機制就是 JavaScript 的救星。當遇到需要等待的任務（例如讀取檔案、計時器、向伺服器發送 AJAX 請求）時，JavaScript 會把任務丟到背景去處理，自己繼續回頭執行後面的程式碼，確保使用者介面永遠保持流暢、不卡頓。

同步與非同步核心比較表

比較項目 同步 (Synchronous) 非同步 (Asynchronous)
執行方式 一步一步依序執行，排隊進行 多個任務並行或背景處理，不卡死主線
是否阻塞 (Blocking) 是。上一個沒做完，後面全得等 否。發出請求後立刻往下走
使用者體驗 容易造成畫面卡頓、操作不流暢 畫面保持靈活、反應即時
常見應用情境 簡單的變數宣告、數學運算、陣列處理 API 串接 (AJAX/Fetch)、讀取檔案、計時器、計費扣款
